# 智衡 Copilot 操作手册

本文档面向开发/测试人员，介绍系统默认账号、登录方式、项目与任务创建、成员角色分配及密码修改等常见操作。

## 1. 默认账号

首次启动并执行数据库迁移后，系统会自动创建两个默认账号：

| 登录名 | 默认密码 | 角色 | 说明 |
|---|---|---|---|
| `admin` | `admin-dev-only` | 系统管理员 | 拥有全部权限 |
| `demo` | `demo-dev-only` | 普通用户 | 仅拥有被分配项目的权限 |

默认密码可在 [`docker-compose.yml`](../docker-compose.yml) 中通过环境变量修改：

- `SEED_ADMIN_PASSWORD`
- `SEED_DEMO_PASSWORD`

## 2. 登录并获取 Token

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "login": "admin",
  "password": "admin-dev-only"
}
```

成功响应示例：

```json
{
  "token": "<bearer-token>",
  "expires_at": "2026-08-18T01:00:00Z",
  "user": {
    "id": 1,
    "login": "admin",
    "name": "系统管理员",
    "is_admin": true
  }
}
```

后续所有受保护接口需在请求头中携带：

```
Authorization: Bearer <bearer-token>
```

## 3. 创建新账号

当前系统**未提供公开的用户注册/创建接口**。新增用户只能通过以下方式：

1. **直接操作数据库**：向 `user_account` 表插入记录，`password_hash` 字段需使用后端 `app.core.security.hash_password` 生成。
2. **扩展 Alembic migration**：在 seed 数据中增加账号，与 `admin`/`demo` 的创建方式一致。

后续如需前台创建账号，可补充 `POST /api/v1/users` 接口。

## 4. 创建新项目

```http
POST /api/v1/projects
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "XX 客户项目",
  "customer_name": "XX 客户",
  "project_type": "软件销售",
  "parties": [{ "role": "甲方", "name": "XX 客户" }],
  "signed_date": "2026-01-01",
  "started_date": "2026-01-05",
  "planned_delivery_date": "2026-06-30",
  "status": "active",
  "progress": 10
}
```

权限说明：

- 系统管理员（`is_admin = true`）可直接创建项目。
- 普通用户必须是某个现有项目的 `manager`，才能创建新项目。
- 项目创建成功后，创建者会自动成为该项目的 `manager`。

## 5. 创建 AI 任务

### 5.1 生成项目总结

```http
POST /api/v1/projects/{project_id}/summary
Authorization: Bearer <token>
```

返回任务 ID，可通过 `GET /api/v1/tasks/{task_id}` 轮询执行状态。

### 5.2 根据回答重新生成总结

```http
POST /api/v1/projects/{project_id}/summary/answers
Authorization: Bearer <token>
Content-Type: application/json

{
  "answers": [
    { "question": "当前进度如何？", "answer": "已完成 80%" }
  ]
}
```

### 5.3 解析合同 / 发票 / 回款单据

```http
POST /api/v1/versions/{version}/extract
Authorization: Bearer <token>
```

`version` 为文件版本哈希，对应 `FileVersion` 的 `version` 字段，且该版本的 `document_type` 需为 `contract`、`invoice` 或 `payment`。

## 6. 分配项目负责人

当前系统**未提供单独的成员管理接口**，项目负责人的产生方式如下：

- **自动成为负责人**：创建项目时，创建者自动写入 `project_member` 表，角色为 `manager`。
- **管理员天然具备权限**：管理员访问任何项目时均不校验 `project_member` 记录。

如需将其他用户变更为某项目的负责人，目前需直接修改 `project_member` 表，将其 `role` 设为 `manager`。

## 7. 分配项目普通工作人员

当前系统**未提供将用户添加为普通工作人员的接口**。数据库模型已支持该角色，可通过直接操作数据库实现：

```sql
INSERT INTO project_member (project_id, user_id, role)
VALUES (1, 2, 'implementer');
```

`role` 可选值：

- `manager`：项目负责人，可管理项目、上传文件、创建交付物等。
- `implementer`：项目普通工作人员，可查看项目、上传文件，但不能管理项目元数据。

## 8. 修改密码

当前系统**未提供修改密码接口**。如需修改用户密码，请直接操作数据库：

1. 进入后端容器或连接数据库。
2. 使用后端 `app.core.security.hash_password("新密码")` 生成 `password_hash`。
3. 更新 `user_account` 表的 `password_hash` 字段。

示例（在容器内执行 Python）：

```python
from app.core.security import hash_password
print(hash_password("new-password"))
```

## 9. 常用 API 速查

| 方法 | 路径 | 说明 | 最小权限 |
|---|---|---|---|
| POST | `/api/v1/auth/login` | 登录 | 无 |
| GET | `/api/v1/auth/me` | 获取当前用户信息 | 已登录 |
| GET | `/api/v1/projects` | 项目列表 | 已登录 |
| POST | `/api/v1/projects` | 创建项目 | admin / manager |
| GET | `/api/v1/projects/{id}` | 项目详情 | 项目成员 |
| PATCH | `/api/v1/projects/{id}` | 更新项目 | admin / manager |
| POST | `/api/v1/projects/{id}/files` | 上传工作区文件 | admin / manager / implementer |
| POST | `/api/v1/projects/{id}/tracked-files` | 将文件提升为交付物 | admin / manager |
| POST | `/api/v1/projects/{id}/summary` | 创建项目总结任务 | 项目成员 |
| POST | `/api/v1/versions/{version}/extract` | 创建单据解析任务 | 项目成员 |
| GET | `/api/v1/statistics/overview` | 统计看板 | 已登录 |
