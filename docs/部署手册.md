# 智衡 Copilot 部署手册

> 本手册覆盖两种部署方式：
>
> - **生产部署（推荐）**：见第 3 章，`docker compose up -d --build` 一条命令完成，nginx 容器托管前端静态文件并在同域下反代 `/api`，公网仅暴露 web 一个端口。
> - **预览 / 开发方式**：见第 4 章起，`build-and-start.ps1` 一键脚本（前端 vite preview + 后端容器），仅用于测试阶段快速体验。

## 1. 交付范围

当前版本已包含以下能力，用户可直接通过浏览器访问体验：

- 登录与默认账号（系统管理员 / 普通用户）
- 系统管理：账号创建、删除、管理员权限设置与 AI 配置
- 项目详情页：项目成员分配（项目负责人 `manager` / 项目成员 `implementer`，仅管理员可见）
- 项目创建（项目编号自动生成）
- 项目工作区文件上传、交付物追踪
- 项目快照与标签时间线
- AI 任务：项目总结、合同 / 发票 / 回款单据解析
- 统计看板与风险监测

## 2. 环境准备

生产部署仅需：

- 操作系统：Linux（或 Windows Server）
- Docker >= 24.0（Windows 建议 Docker Desktop）
- Docker Compose >= 2.20
- 公网 IP（安全组 / 防火墙放行 web 端口，默认 8080）

预览 / 开发方式额外需要：Node.js >= 20、npm >= 10、PowerShell Core。

## 3. 生产部署（同机同域，推荐）

### 3.1 架构说明

一条命令拉起三个容器：

| 服务 | 说明 | 端口 |
|---|---|---|
| `web` | nginx：托管前端构建产物，同域反代 `/api` 到 api 容器 | `${WEB_PORT:-8080}:80`，公网唯一入口 |
| `api` | uvicorn：启动时先自动执行 `alembic upgrade head` 完成数据库迁移 | `127.0.0.1:8086:8000`，仅本机 |
| `db` | PostgreSQL | `127.0.0.1:8088:5432`，仅本机 |

公网暴露已收口：只有 web 端口对外可达；api 与 db 仅绑定回环地址，供服务器本机开发工具与 vite proxy 使用，本机开发与联调流程不受影响。

### 3.2 配置环境变量

```bash
cp .env.example .env
```

然后编辑 `.env`。**生产环境必须修改 `POSTGRES_PASSWORD`、`SEED_ADMIN_PASSWORD`、`SEED_DEMO_PASSWORD`**，其余变量按需调整（详见 `.env.example` 注释）。同机同域部署下前端经 nginx 反代访问 `/api`，无需配置 `CORS_ORIGINS`。

### 3.3 一条命令启动

```bash
docker compose up -d --build
```

启动完成后，浏览器访问：

```
http://<公网IP>:${WEB_PORT}    # 默认 http://<公网IP>:8080
```

### 3.4 自动迁移与数据卷

- api 容器启动命令会先执行 `alembic upgrade head`，数据库表结构自动迁移到最新版本，无需手工干预。
- 数据持久化在两个 Docker Volume 中：`pg_data`（数据库）、`api_data`（上传文件等工作区数据）。
- `docker compose down` 后再 `up` 数据仍在；只有 `docker compose down -v` 才会删除数据卷，请勿在生产环境使用。

### 3.5 首次启动后的必做事项

1. 立即使用 `admin` 账号登录，进入“管理”页面**修改管理员密码**。
2. 在同一页面**删除 `demo` 账号**（或修改其密码予以接管），避免默认账号被外部利用。

### 3.6 排障命令

```bash
docker compose ps                          # 查看各服务健康状态（应全部为 healthy）
docker compose logs -f web                 # 查看 web / api / db 日志（按需替换服务名）
docker compose up -d --build --force-recreate   # 修改代码或配置后重建
curl -i http://localhost:8080/             # 服务器本机验证 web（应返回 200）
curl -i http://127.0.0.1:8086/api/v1/health     # 服务器本机验证 api
```

回滚到上一个可用版本：

```bash
git checkout <上一个可用提交>
docker compose up -d --build
```

### 3.7 公网暴露核验

从另一台机器（或本机使用公网 IP 而非 localhost）验证：

- 访问 `http://<公网IP>:8086/api/v1/health` 应**连接失败**（api 未对公网开放）
- 访问 `http://<公网IP>:8080` 应正常打开登录页，且直接刷新 `/projects/1` 等前端路由不 404

### 3.8 后续 HTTPS（本期不实现）

当前为 HTTP 明文部署。后续拥有域名后，可在 web 服务前挂一层 Caddy（自动签发与续期证书），或为 web 的 nginx 配置证书并监听 443，再将 80 重定向到 443。本期不实施。

### 3.9 后续硬化（本期不实施，仅列明）

- 去除 api 启动命令中的 `--reload`（生产应使用固定进程模式）
- 去除 api 的源码挂载（`./server:/app`），改为镜像内固定代码
- HTTPS 改造（见 3.8）

## 4. 预览 / 开发方式：配置环境变量

在仓库根目录创建 `.env` 文件，Docker Compose 会自动读取。最小配置如下：

```env
CORS_ORIGINS=http://<服务器公网IP>:4173,http://localhost:4173
SEED_ADMIN_PASSWORD=ChangeMe2026!
SEED_DEMO_PASSWORD=Demo2026!
LLM_PROVIDER=mock
```

说明：

- `CORS_ORIGINS` 必须包含前端预览地址 `http://<服务器公网IP>:4173`，否则浏览器请求会被后端拒绝。
- `SEED_ADMIN_PASSWORD` 和 `SEED_DEMO_PASSWORD` 用于首次启动时创建默认账号。
- `LLM_PROVIDER=mock` 表示 AI 使用模拟数据；如需真实解析，改为 `kimi` 并填写 `KIMI_API_KEY`。

## 5. 预览 / 开发方式：一键启动

```powershell
cd zhiheng-copilot
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\build-and-start.ps1
```

`build-and-start.ps1` 会依次执行：

1. `cd client && npm run build`：构建前端生产包
2. `docker compose up --build -d`：启动后端 API 与 PostgreSQL
3. `npm run preview -- --host`：启动前端预览服务器（已绑定 `0.0.0.0`，允许公网访问）

脚本会一直占用前台，按 `Ctrl+C` 退出时自动执行 `docker compose down`。

## 6. 访问服务

启动成功后，通过浏览器访问：

| 服务 | 地址 |
|---|---|
| 前端页面 | `http://<服务器公网IP>:4173` |
| 后端 API | `http://127.0.0.1:8086`（仅服务器本机，已绑定回环地址） |
| 数据库 | `localhost:8088`（仅服务器本地） |

注意：安全组或防火墙需要放行 `4173`（前端预览）。如需完整的公网访问体验（前端页面与 `/api` 同域可用），请使用第 3 章的生产部署方式。

## 7. 验证部署

登录接口测试（api 端口已绑定回环地址，请在服务器本机执行）：

```bash
curl -X POST http://127.0.0.1:8086/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"admin","password":"ChangeMe2026!"}'
```

返回 `token` 即表示后端运行正常。

浏览器访问前端页面后，建议验证：

- 使用 `admin` 账号登录
- 进入“系统管理”页面创建新账号
- 创建新项目
- 分配项目负责人 / 项目成员
- 上传文件并触发 AI 任务

## 8. 默认账号与使用说明

首次启动后系统会自动创建：

| 登录名 | 密码 | 角色 |
|---|---|---|
| `admin` | `.env` 中 `SEED_ADMIN_PASSWORD` 的值 | 系统管理员 |
| `demo` | `.env` 中 `SEED_DEMO_PASSWORD` 的值 | 普通用户 |

管理员登录后，可在顶部导航进入“管理”页面创建账号并维护 AI 配置；项目成员在项目详情页的“项目成员”标签中分配（仅管理员可见该标签）。

## 9. 安全注意事项

- [ ] 首次部署后务必修改 `.env` 中的 `POSTGRES_PASSWORD`、`SEED_ADMIN_PASSWORD`，并在首次登录后于管理页再次修改 admin 密码；若不需要演示账号，在 `.env` 中显式设置 `SEED_DEMO_PASSWORD=`（空值）即可让迁移跳过 demo 账号创建（对已建库的存量环境，改为登录管理页删除 demo 账号）
- [ ] `CORS_ORIGINS` 只写实际访问地址，不要填 `*`（生产同域部署无需配置）
- [ ] 数据库 `8088` 与 api `8086` 已仅绑定 `127.0.0.1`，公网只放行 web 端口（默认 8080）
- [ ] `AUTH_DISABLED` 保持 `false`
- [ ] 预览阶段使用 HTTP 即可，正式上线前再补充 HTTPS（见 3.8）

## 10. 停止与重启

- 停止：在运行 `build-and-start.ps1` 的窗口按 `Ctrl+C`，脚本会自动停止前端预览并执行 `docker compose down`
- 重启：再次运行 `.\build-and-start.ps1`

如果只需要停止后端，可另开一个终端执行：

```powershell
docker compose down
```

## 11. 常见问题

### 11.1 前端登录提示“请求失败”

- 浏览器 F12 查看具体报错，确认是 CORS 问题还是后端未启动
- 检查 `.env` 中 `CORS_ORIGINS` 是否包含 `http://<服务器公网IP>:4173`
- 检查后端容器状态：`docker compose ps`

### 11.2 数据库连接失败

- 检查 PostgreSQL 容器是否健康：`docker logs zhiheng-copilot-db-1 --tail 50`
- 检查 `DATABASE_URL` 中的主机名是否为 `db`

### 11.3 文件上传失败

- 检查 `api_data` Docker Volume 是否挂载成功
- 检查容器内 `/data` 目录是否有写入权限

### 11.4 修改密码

管理后台已支持修改密码：管理员登录后进入“管理”页面即可为账号改密，无需手工操作数据库。
